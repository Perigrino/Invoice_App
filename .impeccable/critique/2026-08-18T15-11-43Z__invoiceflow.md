## Design Specificity Verdict

Surface authorship is strong — the LandingView's staggered invoice-card reveal, monospaced money numerals, green-on-navy identity, and client initial-avatars say "billing tool," not "generic CRUD template." But that specificity lives in presentation. The working screens collapse into category-interchangeable cards and sheets, and the app force-forces dark while shipping a dead "Dark Mode" toggle. Verdict: ~75% surface authorship, ~25% product authorship.

## Overall Impression

Coherent dark system with genuinely good money-rendering instincts, dragged down by invisible state (nothing confirms a save) and a broken first trust test (creating a client silently fails). The single biggest opportunity: make every money action confirm itself and make the primary flow honest about what it did.

## What's Working

1. A real design system: shared tokens (brandPrimary/brandSurface/brandBorder), one card anatomy, one empty-state component — one visual voice across Invoices, Clients, Settings.
2. Money rendered like money: monospaced numerals, right-aligned fixed-width total columns — scannable and trustworthy.
3. Guardrails where cheap: destructive delete alerts with consequence copy, Enter/Escape shortcuts on sheets, live subtotal/discount/tax recalculation.

## Priority Issues

**[P0] New Client silently fails to persist.** ClientFormView.saveClient() inserts and dismisses; the client never appears in ClientListView or the invoice form's picker. It's the first-timer's first trust test and the app just betrays it with zero feedback.
Fix: guarantee persistence, then show a persistent success confirmation; offer "Add New Client…" inline in the invoice form's picker.

**[P1] Single-click opens the Edit modal.** Both lists launch the edit sheet via onChange(of: selection) (InvoiceListView.swift:69-74, ClientListView.swift:53-58). Violates macOS selection conventions, makes accidental modal edits routine, kills multi-select/bulk, pushes View Details into a right-click-only corner.
Fix: selection = selection; open detail on double-click or in a detail column; Edit lives in toolbar/context menu.

**[P1] High-stakes moments have no closure; Cancel has no guard.** Create/Update/Duplicate/Export all complete invisibly; Cancel discards filled work silently.
Fix: unsaved-changes confirmationDialog on Cancel, "Invoice INV-… created" on save, visible result for Duplicate/Export.

**[P1] The Dark Mode toggle is dead and the settings model drives nothing.** ContentView.swift:163 hard-codes .dark; GeneralSettingsView toggles setting.darkMode which nothing reads. PDFGenerator hard-codes A4, #1E3A5F accent, and USD, ignoring template/paperSize/pdfAccentColor/currency/dateFormat/separator/signPlacement/decimalPlaces and every show* flag. Users configure ~15 settings that never reach output.
Fix: drive preferredColorScheme from the active Setting; pass the Setting into PDFGenerator and apply it.

**[P1] Controls are unlabeled for VoiceOver.** Toggle("", …)/Picker("", …)/DatePicker("", …) with .labelsHidden() and an unlinked sibling Text is systemic (SettingsUI.toggle/pickerRow, every picker in InvoiceFormView, both ColorPickers). WCAG 1.3.1.
Fix: put the label inside the control or set .accessibilityLabel per control.

**[P1] Duplicating an invoice drops its line items.** InvoiceListView.swift:110-125 copies totals but not lineItems — the duplicate shows a total with an empty detail table.
Fix: clone each InvoiceLineItem and recalculate.

**[P2] Validation errors are transient and misplaced.** Shown as a caption in the form header, auto-hidden after 3s even while invalid (InvoiceFormView.swift:373-384).
Fix: inline field-level errors (red border + message at the row), persistent while invalid.

**[P2] Detail view is undiscoverable, incomplete, and has a display bug.** Reachable only via right-click; no Edit button; formats the tax rate as currency (InvoiceDetailView.swift:88 shows "+$10.00" for a 10% rate); Balance Due always equals Total and is always red.
Fix: make detail the default drill-in, add Edit, format rates as percents, gate Balance Due on an actual balance.

## Persona Red Flags

**Jordan (first-timer):** Lands on "No Invoices / Create your first invoice" with no button in the empty state; the CTA is only in the toolbar. The client picker offers "No Client" with no inline add; tab-switching to Clients then silently fails. Every step rewards a dead end or vanishing data.

**Alex (power user):** Selection is hijacked into an edit modal, so no multi-select/bulk/status filter. Invoices get random INV-<6 chars> numbers instead of a sequence — impossible to cross-reference accounting. No Cmd+N, no filtering by draft/sent/paid.

**Sam (accessibility-dependent):** Forced dark with a dead Dark Mode toggle — no light mode and no Reduce Motion handling (LandingView's 8-animation chain ignores accessibilityReduceMotion). Discount/tax/balance figures are color-only (red/green). Errors auto-hide in 3s (WCAG time limit). .caption (11pt) labels everywhere.

## Minor Observations

- LandingView is the onboarding gate (InvoiceFlowApp.swift:14) and runs once on fresh installs — the animation is the peak, so keep it but honor Reduce Motion.
- InvoiceDetailView renders stored percentages as currency; detail table drops the Disc % column the form has.
- Currency setting doesn't propagate to InvoiceRow's formatCurrency (always USD default).
- Mixed save models in Settings: Profile requires explicit Save; other three tabs autosave per keystroke.
- EmptyStateView has no CTA button.
- Client email on the trailing row edge crowds narrow columns.
- Fixed .system(size:) fonts don't scale with macOS accessibility font settings.
- PDF export opens Preview directly via NSWorkspace.open — no save panel, synchronous main-thread generation.

## Questions to Consider

1. If the app force-forces dark while shipping a dead Dark Mode toggle, is the identity "an opinionated billing tool" or "a PDF cosmetic control panel"?
2. Why does the most polished screen (animated invoice card) sit in a once-run onboarding flow while real money moments close in silence?
3. If Balance Due always equals Total and there's no paid/overdue concept, what is InvoiceFlow's actual model of getting paid?
4. Seven currencies, five templates, four languages — how many settings are alive in the user's view versus dead promises?
